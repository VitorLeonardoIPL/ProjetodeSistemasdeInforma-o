1Perceber o que se pede e a referência (Books_Login)Books_Login · Especificação
O que se pede

Fazer só duas coisas na app Android do FrotaGest: a janela de login e o menu hamburguer (Navigation Drawer). O código tem de ser o das aulas: é o da Ficha 4 de AMSI ("Books – Navegação e Fragmentos"), que está feito na pasta Books_Login. Só mudam os textos, as cores e os itens do menu, porque a app é outra.

LoginActivity→ Intent + email →MenuMainActivity→DrawerLayout (Toolbar + NavigationView)
Como é o código de referência (Books_Login)
  • LoginActivity: ViewBinding, valida o email com Patterns.EMAIL_ADDRESS e a palavra-passe com 4 ou mais caracteres. Se estiver tudo certo, abre a MenuMainActivity e leva o email num extra do Intent.
  • MenuMainActivity: um DrawerLayout com MaterialToolbar, um FrameLayout (fragmentContainer) e um NavigationView. O NavigationView junta o cabeçalho (nav_header_main) ao menu (menu_main).
  • A Ficha 4 faz o clique nos itens e os fragmentos nos passos seguintes (5.4 a 8). Isso não faz parte deste pedido: tocar num item não faz nada, por agora.
O que diz a especificação (Word)
  • O login (Figura 34) tem o logótipo, "FrotaGest", os campos Email e Palavra-passe, o botão Entrar e a ligação Esqueci-me da palavra-passe.
  • Os separadores do Colaborador no documento são Pedidos, Viagem e Perfil. São esses os três itens do menu.
  • Decisão do grupo, por agora: só o Colaborador usa a app. Os outros roles usam o website. O documento será corrigido mais tarde.
Atenção: o documento desenha uma barra inferior com 3 separadores. Aqui trocamos por menu hamburguer, como na ficha.
Verifica: percebes que o login e o menu copiam a ficha e que o resto da app (API, pedidos, viagem) fica para depois.

O que é

O ViewBinding cria, para cada layout XML, uma classe Java com um campo por cada componente que tem id. Em vez de findViewById(R.id.etEmail) escreve-se binding.etEmail. O layout activity_login.xml dá a classe ActivityLoginBinding.

O que fazer

Em app/build.gradle.kts, dentro de android { }, antes do defaultConfig:

app/build.gradle.kts


Depois clica em Sync Now na barra amarela do Android Studio.


Porquê


  • É o que a ficha faz. Sem isto, as classes ActivityLoginBinding, ActivityMenuMainBinding e NavHeaderMainBinding não existem e o Java dá erro.
  • O nome da classe vem do nome do ficheiro: activity_menu_main.xml → ActivityMenuMainBinding (maiúscula em cada palavra, sem _, mais Binding). O id tvEmail passa a ser o campo tvEmail.


Verifica: o Sync termina sem erros. As classes de binding só aparecem depois de compilares (passo 12).

6LoginActivity.javacom.example.frotagestandroid/LoginActivity.java



O que é


A classe que valida os dados e abre o menu. É o código do Books, linha a linha.


O que fazer


Cria a classe LoginActivity (New → Java Class, na pasta do pacote) com este código:


LoginActivity.java


Explicação, por partes


  • Binding: ActivityLoginBinding.inflate(getLayoutInflater()) transforma o XML em objetos; setContentView(binding.getRoot()) mostra-os. A partir daí binding.etEmail é o campo de email.
  • EdgeToEdge.enable(this): a app desenha por baixo das barras do sistema. É o que o Android Studio gera por omissão.
  • onClickLogin: lê o texto dos dois campos. Se o email não for válido, setError mostra o aviso no campo e o return pára tudo. O mesmo para a palavra-passe.
  • isEmailValido: Patterns.EMAIL_ADDRESS é um padrão pronto do Android; .matcher(email).matches() diz se o texto tem forma de email.
  • isPasswordValida: exige 4 ou mais caracteres.
  • Intent: "abre este ecrã". putExtra("EMAIL", email) leva o email como chave/valor. startActivity abre a MenuMainActivity e finish() fecha o login (o botão Voltar não regressa a ele).


O que mudou em relação ao Books


  • O pacote (com.example.frotagestandroid) e o import do binding.
  • Retirei os imports que não se usavam e os blocos de código que estavam em comentário. A lógica é a mesma.


Atenção: a validação é local, como na ficha: qualquer email válido e palavra-passe de 4 caracteres entram. Ainda não há API nem verificação do role.


Verifica: compila. Ainda não corre, porque falta a MenuMainActivity.

O que é


O ecrã principal. O DrawerLayout é a raiz e tem dois filhos: o conteúdo (toolbar + área dos fragmentos) e a gaveta (NavigationView).


O que fazer


Cria a Empty Views Activity MenuMainActivity (como diz o ponto 1 da ficha) e substitui o conteúdo do XML:


res/layout/activity_menu_main.xml


Porquê


  • DrawerLayout: o primeiro filho é o que se vê sempre; o segundo (com layout_gravity="start") é a gaveta que desliza da esquerda. tools:openDrawer="start" só a mostra aberta na pré-visualização.

Perguntas para o estudo


Para que serve o ViewBinding?
Cria uma classe por layout com um campo por cada id. Evita o findViewById e os erros de escrever mal o id ou de usar o tipo errado.


Porque é que o login faz finish() depois do startActivity?
Para fechar o login. Se não fechasse, o botão Voltar do telemóvel voltava ao login, já com a sessão "aberta".


O que é um Intent e o que é o putExtra?
O Intent é o pedido "abre este ecrã". O putExtra(chave, valor) leva dados junto; o outro ecrã lê-os com getIntent().getStringExtra(chave).


Qual a diferença entre setError e um Toast?
O setError mostra o aviso no próprio campo, a vermelho, e fica até se corrigir. O Toast é uma mensagem curta que desaparece. A ficha usa setError na validação.


Para que serve o DrawerLayout?
É o contentor que sabe ter uma gaveta que desliza do lado. O primeiro filho é o conteúdo; o filho com layout_gravity="start" é a gaveta.


O que faz o ActionBarDrawerToggle?
Liga a toolbar à gaveta: mostra o botão das três linhas, abre/fecha a gaveta ao tocar e anima o ícone. O syncState() acerta o ícone com o estado da gaveta.


Porque é que o cabeçalho do menu não se acede como o resto do ecrã?
Porque está dentro do NavigationView e tem o seu próprio layout. Vai-se buscar com getHeaderView(0) e cria-se o binding dele com NavHeaderMainBinding.bind(...).


Para que serve o checkableBehavior="single"?
Faz os itens do grupo marcáveis, e só um de cada vez. É o que dá o item "selecionado" no menu.


Porque é que não se pode usar switch com R.id.navPedidos?
Desde o Android Gradle Plugin 8 os ids deixaram de ser constantes. Por isso a ficha usa if (id == R.id.navEstatico) … else ….


Erros que podem aparecer


Cannot resolve symbol ActivityLoginBinding
O ViewBinding não está ativo ou falta compilar. Confirma o buildFeatures { viewBinding=true }, faz Sync Now e Build → Make Project.


A app fecha logo que carrego em Entrar
Abre o Logcat e procura ActivityNotFoundException: a MenuMainActivity não está registada no Manifest.


A app fecha ao abrir o menu, com NullPointerException
O getStringExtra("EMAIL") deu null. A chave tem de ser igual nos dois lados e o menu só deve ser aberto a partir do login.


O menu não mostra os ícones
Confirma que os 3 ficheiros ic_nav_*.xml estão em res/drawable e que os android:icon do menu_main.xml têm os mesmos nomes.


Os itens do menu não aparecem na pré-visualização
Falta o tools:showIn="navigation_view" na etiqueta <menu>.


A barra de cima fica da cor errada
Falta o colorPrimary no tema (nos dois themes.xml) ou o android:background="?attr/colorPrimary" na toolbar.


O ícone das três linhas não aparece
Falta o setSupportActionBar e o ActionBarDrawerToggle (carregarToolbar()), ou o tema não é NoActionBar (ficaria com duas barras).


Mudei um ficheiro XML e nada mudou
Corre a app outra vez (▶). Alterações em XML e Java só aparecem depois de recompilar.
